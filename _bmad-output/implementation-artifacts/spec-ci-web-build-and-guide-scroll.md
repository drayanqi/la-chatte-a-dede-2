# Fix CI web image build and jsdom scrollIntoView unhandled error

## Intent

**Problem:** The CI `docker buildx build` of the web image failed at Rollup — `src/lib/scriptingGuide.ts` imports 6 assets from `docs/scripting/img/`, but `.dockerignore` excluded the whole `docs/` tree from the build context. Separately, the GuidePage TOC click test threw `scrollIntoView is not a function` as an unhandled Vitest error: jsdom does not implement the method, so the optional-chain guard on the element does not help.

**Approach:** Keep the Docker context tight by un-ignoring only `docs/scripting/img` (the canonical 4-line nested negation) instead of the whole `docs/` tree, preserving the "one source of truth" design where the in-app guide bundles the docs-pipeline assets. Stub `Element.prototype.scrollIntoView` with a `vi.fn()` in the global Vitest setup, alongside the existing ResizeObserver/matchMedia stubs.
